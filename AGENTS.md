# Устав ИИ-агента для проекта PrimakovApp

Данный файл содержит жесткие ограничения и правила для работы модуля ECC. Нарушение этих правил приведет к сбросу цикла.

НИКОГДА НЕ ПУШ В РЕПОЗИТОРИЙ БЕЗ МОЕГО ПОДТВЕРЖДЕНИЯ

## 1. Стек технологий
*   **Backend:** Node.js 20.x, Express.js 4.18.2, TypeScript 5.3+.
*   **База данных:** PostgreSQL 14+ (взаимодействие через `pg` pool, без тяжелых ORM, если они не внедрены ранее).
*   **Frontend (Mobile):** Flutter 3.0.0+, Dart 3.0.0+.
*   **Стейт-менеджмент и сеть (Frontend):** Riverpod 2.x, Dio 5.x.
*   **Тестирование:** Jest (для бэкенда).

## 2. Архитектурные ограничения
*   **Clean Architecture:** Бэкенд должен строго соблюдать разделение на 4 слоя: `Presentation` (Controllers/Routes) -> `Application` (Use Cases) -> `Domain` (Entities/Value Objects) -> `Infrastructure` (Repositories).
*   **Изоляция слоев:** Контроллеры **НЕ ИМЕЮТ ПРАВА** напрямую вызывать SQL-запросы или обращаться к БД. Вся работа с данными идет только через интерфейсы репозиториев (`Repository Pattern`).
*   **Обработка ошибок:** Использовать `Result Pattern`. Use Cases должны возвращать объект с полями успешности (`isSuccess`, `isFailure`, `value`, `error`), а не выбрасывать необработанные исключения (`try/catch` внутри контроллеров должен перехватывать только фатальные сбои).

## 3. База данных и Безопасность
*   **Ключи:** Использовать `UUID` для всех первичных ключей (`id`).
*   **Пароли:** Строго хешировать через `bcrypt` (10 rounds). Никогда не возвращать хеш пароля в клиентских ответах.
*   **Авторизация:** JWT-токены. Срок жизни токена — 7 дней. В payload токена должны быть `userId`, `email` и `role`.
*   **RBAC (Управление доступом):** На уровне `middleware` проверять роли пользователей (например, студент не может смотреть чужие оценки).

## 4. Правила рабочего цикла (ECC Workflow)
*   **Strict TDD:** Запрещено писать логику (implement), пока не написаны падающие интеграционные или модульные тесты (test).
*   **Ориентация на результат:** Если текущая логика сломана — чинить автономно. Цель — работающий продукт.
*   **Автономность:** Запрашивать вмешательство человека (human-in-the-loop) **ТОЛЬКО** при успешном завершении этапа `verify` (когда все тесты зеленые, а фича работает в UI).
*   **Никаких заглушек:** Если кнопка в UI есть, она должна делать реальный запрос к API, обрабатывать загрузку и показывать ответ/ошибку.
